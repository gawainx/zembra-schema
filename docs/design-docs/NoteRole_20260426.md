# NoteRole_20260426

## 核心功能（WHAT）

为 Zembra Note schema 增加 `role` 字段，用于记录一条 Note 创建时的角色来源。字段只允许 `Human` 和 `Agent` 两个固定大小写枚举值，分别表示人类创建的笔记和 Agent 创建的笔记。

### 需求背景（WHY）

Zembra 需要面向人类用户和 Agent 同时使用，并适配 OpenClaw、Hermes 等 Agent 应用场景。当前 `notes` 表只保存正文、领域、生命周期状态和当前版本引用，无法在数据层区分人类创建内容和 Agent 创建内容。

### 需求目标（GOAL）

- 在 `notes` 数据模型中记录创建角色。
- 旧数据升级后全部默认归属 `Human`。
- `role` 创建后不允许通过 schema 表达普通更新语义。
- JSON Schema、SQLite 初始 DDL、迁移脚本和导出版本号保持一致。
- schema 版本从 `0.1.0` 升级到 `0.2.0`，完成后打对应 Git tag。

### 范围边界

In Scope:

- 修改 `notes.role` 的 SQLite 表结构、约束和索引策略。
- 修改 `json/note.schema.json` 的字段契约。
- 修改 `json/zembra_note_export.schema.json` 的 `schema_version`。
- 新增从 `0.1.0` 到 `0.2.0` 的迁移脚本。
- 更新 `note_schema.md` 和 `CHANGELOG.md`。
- 完成 Git commit 和 `v0.2.0` tag。

Out of Scope:

- 不新增独立 actor、user、agent profile 表。
- 不追踪 Agent 名称、模型、供应商、运行任务或执行链路。
- 不在 `note_revisions` 中保存 role 快照，因为 role 是创建角色，不随内容版本变化。
- 不实现应用层禁止修改逻辑，只在 schema 中表达字段约束和迁移结果。

## 实现流程（HOW）

当前架构由三类契约组成：

- `sqlite/001_initial_schema.sql`：最新完整 SQLite DDL。
- `migrations/001_initial_schema.sql`：初始版本迁移。
- `json/*.schema.json`：跨端对象级 JSON Schema。

最终技术决策：

- 在 `notes` 表增加 `role TEXT NOT NULL DEFAULT 'Human' CHECK (role IN ('Human', 'Agent'))`。
- 在 `json/note.schema.json` 增加 `role` 属性，使用 `enum: ["Human", "Agent"]`，并加入 `required`。
- 新增 `migrations/002_add_note_role.sql`，通过 `ALTER TABLE notes ADD COLUMN` 为旧库补齐字段，并记录 `schema_migrations` 版本 `0.2.0`。
- 更新导出 schema 的 `schema_version` const 到 `0.2.0`。
- 不在 `note_revisions` 增加 role 字段，避免把创建角色误表达成可随版本变化的内容快照。

关键约束：

- `role` 值大小写固定为 `Human` / `Agent`。
- 旧数据迁移后全部获得默认值 `Human`。
- schema 层只限制合法枚举；应用层需要把 role 当作创建后不可变字段处理。
- SQLite `ALTER TABLE ADD COLUMN` 使用非空默认值，保证已有记录可迁移。

## 测试用例

编译检查:

- 用 SQLite 执行 `sqlite/001_initial_schema.sql`，确认完整建库成功。
- 用 SQLite 执行 `migrations/001_initial_schema.sql` 后再执行 `migrations/002_add_note_role.sql`，确认升级成功。

回归检查:

- 插入不带 `role` 的旧风格 note，确认默认值为 `Human`。
- 插入 `role = 'Agent'` 的 note，确认成功。
- 插入非法 role，例如 `agent`，确认 CHECK 约束拒绝。
- 验证 `json/note.schema.json` 接受 `Human` / `Agent`，拒绝非法枚举。

手工检查:

- 检查 `note_schema.md` 字段说明与 DDL、JSON Schema 一致。
- 检查 `CHANGELOG.md` 已记录 `0.2.0`。
