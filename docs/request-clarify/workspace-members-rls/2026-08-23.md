# Workspace Members 与 Supabase RLS 需求澄清

## 需求理解

Zembra WebUI 部署到 Vercel 后，已登录的 Supabase Auth 用户直接访问 Supabase 数据库。`workspace_members` 是 Auth 用户与 workspace 的正式关系，RLS 以该关系决定数据访问范围。

## 已确认决策

- 已有 Supabase 数据库严格对齐 `0.5.0`，迁移必须原地升级并保留全部已有数据。
- `workspace_members` 的唯一成员角色为 `manager`。
- WebUI 不创建 workspace，也不管理成员关系。
- WebUI 可以读取和编辑 workspace 业务数据。
- WebUI 只读取 `sync_changes`、`sync_state`、`sync_conflicts`，不处理同步写入逻辑。

## 迁移路径

先创建 `workspace_members`，再由受控管理员按已有 `workspace_id` 写入对应的 Supabase Auth 用户为 `manager`。确认每个已有 workspace 都存在至少一位 manager 后，启用业务表 RLS。该顺序保证已有业务数据保持原位，并避免在成员关系建立前失去访问权限。

## 范围

本次纳入 Supabase 专属成员关系表、RLS 策略、权限收紧、从 `0.5.0` 的升级脚本、文档和验证。SQLite 不保存 Supabase Auth 身份关系，仅登记统一 `0.6.0` 契约版本。
